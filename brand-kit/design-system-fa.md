# راهنمای سیستم طراحی دیجیتال آهنگ‌بان

**نسخهٔ ۱٫۰ · پیش‌نمایش مفهومی**\
این راهنما برای نمونه‌سازی است. رنگ، کنتراست و رفتار رابط را پیش از عرضه روی دستگاه واقعی و با محتوای دارای مجوز آزمایش کنید.

## ۱. دارایی‌های فنی

- `assets/brand-tokens.css` — متغیرهای CSS برای رنگ، نوع، فاصله و کنترل‌ها.
- `assets/brand-tokens.json` — توکن‌ها برای ابزار طراحی و فرانت‌اند.
- فایل‌های SVG در `assets/` — لوگو، نشان، آیکن و قالب‌های قابل ویرایش.
- `index.html` — پیش‌نمایش محلی، بدون CDN و وابستگی به فونت آنلاین.

## ۲. پالت تک‌رنگ

| توکن | مقدار | کاربرد |
|---|---|---|
| `ink` | `#111111` | متن، لوگوی زمینهٔ روشن، اقدام اصلی |
| `white` | `#FFFFFF` | زمینه و لوگوی زمینهٔ تیره |
| `dark` | `#222222` | سطح تیرهٔ ثانویه |
| `text-muted` | `#666666` | متن فرعی روی سفید |
| `surface` | `#F4F4F4` | کارت و زمینهٔ ثانویه |
| `line` | `#E5E5E5` | مرز و جداکننده |
| `decorative-gray` | `#BDBDBD` | جزئیات تزئینی؛ نه متن کوچک |

لوگو فقط مشکی/سفید است. گرادینت، رنگ برجستهٔ تزئینی و سایهٔ رنگی به سیستم اضافه نکنید.

### زوج‌رنگ‌های پایه

- `#111111` روی `#FFFFFF`: حدود **۱۸٫۹:۱**.
- `#666666` روی `#FFFFFF`: حدود **۵٫۷:۱**.
- `#FFFFFF` روی `#111111`: حدود **۱۸٫۹:۱**.
- `#111111` روی `#F4F4F4`: حدود **۱۸:۱**.

این اعداد فقط کنتراست رنگی همین زوج‌ها را نشان می‌دهند؛ وضعیت focus، اندازهٔ فونت، صفحه‌خوان و تمام حالت‌های رابط باید جداگانه آزموده شوند.

## ۳. تایپوگرافی و شبکه

```css
font-family: "Vazirmatn", Tahoma, Arial, sans-serif;
```

فونت در بسته جاسازی نشده است. پیش از استفادهٔ تجاری، مجوز فونت و روش توزیع آن را بررسی کنید. اگر فونت نصب نیست، fallback سیستمی باید خوانا بماند.

- در عرض ۳۲۰ پیکسل و بزرگ‌نمایی ۲۰۰٪، اسکرول افقی ناخواسته ایجاد نشود.

## ۴. اجزای رابط

### دکمهٔ اصلی

- زمینهٔ مشکی و نوشتهٔ سفید؛ حداقل ارتفاع ۴۸ پیکسل.
- فعل کوتاه و روشن: «پیدا کن»، «گوش بده»، «ارسال برای بررسی».
- focus با خط دور واضح؛ حالت disabled هم دیداری و هم در کد مشخص باشد.

### دکمهٔ ثانویه

- زمینهٔ سفید، نوشته و حاشیهٔ مشکی.
- از چند اقدام هم‌وزن در یک قاب پرهیز کنید؛ یک اقدام اصلی کافی است.

### کارت آهنگ، ویدئو یا پادکست

ترتیب پیشنهادی: کاور مجاز ← نوع محتوا/نسخه ← عنوان ← هنرمند یا سازنده ← اقدام تأییدشده. اگر اطلاعاتی نامطمئن است، حدس نزنید؛ آن را حذف یا «در حال بررسی» بنویسید.

### برچسب دسترسی

- از رنگ به‌تنهایی استفاده نکنید؛ متن وضعیت باید واضح باشد.
- نمونه: «پخش در دسترس»، «دانلود مجاز»، «اجازه در حال بررسی».
- وقتی حق یا قابلیت روشن نیست، اقدام را فعال نکنید.

### جست‌وجو و پیام خطا

- برچسب فیلد مستقل از placeholder باشد.
- placeholder نمونه: «نام آهنگ، هنرمند یا آلبوم».
- پیام خطا از الگوی «چه شد + قدم بعدی» پیروی کند: «پخش انجام نشد. اتصال را بررسی کن و دوباره تلاش کن.»

## ۵. دسترس‌پذیری و حرکت

- کنترل‌ها با صفحه‌کلید قابل استفاده باشند و focus قابل مشاهده داشته باشند.
- متن جایگزین تصاویر محتوایی را بنویسید؛ تصویر تزئینی از فناوری کمکی پنهان شود.
- پخش خودکار صدا نداشته باشید.
- `prefers-reduced-motion` رعایت شود؛ این هویت به حرکت یا انیمیشن نیاز ندارد.
- وضعیت، خطا و مجوز فقط با رنگ منتقل نشوند.
- SVGهای لوگو متن جایگزین مناسب دارند؛ رندر فارسی را در مرورگرها و ابزار طراحی بررسی کنید.

## ۶. نمونهٔ CSS

```css
.button-primary {
  min-height: 48px;
  padding: 12px 20px;
  border: 2px solid #111111;
  border-radius: 999px;
  background: #111111;
  color: #FFFFFF;
  font: 700 1rem/1.4 "Vazirmatn", Tahoma, sans-serif;
}
.button-primary:focus-visible {
  outline: 3px solid #666666;
  outline-offset: 3px;
}
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
  }
}
```
